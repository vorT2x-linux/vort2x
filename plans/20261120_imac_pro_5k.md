# iMac Pro 5K as one tear-free display

## Goal

On the iMac Pro (iMacPro1,1, Radeon Pro Vega 56/64, display engine DCE 12)
the 5K panel is two 2560x2880 tiles on two links. VorT2x's current series
carries the earlier two-tile 5K patch (0003, Atharva Tiwari) plus KAIT2EN's
0013 (adds the iMacPro1,1) and 0014 (scopes the quirk), both by Andre
Eikmeyer. That shows the panel as **two separate displays**: on Kirk's iMac
Pro after the VorT2x install he had to use 2560x1440 on one tile. Fedora's
own kernel gives a single 4K picture.

Bring in the work from `~/Documents/Code/imacPro_amdgpu` (private repo
`KirkDiamond/iMac5k_KaiT2en_support`): Byte's later "amdgpu: add support for
5K" (Atharva Tiwari, Ed Schofield), which merges the two tiles into one
5120x2880 output, plus Kirk's seven patches that add the iMac Pro and make
the merged output work on DCE 12 without a seam tear: per-frame genlock of
the right tile to the left, both tiles latched on the same frame, only
panel commits expanded to both tiles, and a debugfs file to measure the
genlock. iMac20,x (DCN) behaviour stays as Byte's patch has it.

Hardware testing then added three fixes (see Decisions): the right tile's
cursor on DCE (`0003i`), no GSL swap lock for the tiles' flips (`0003j`),
and the per-frame tile reset off by default (`0003k`), which ended the
`flip_done` stalls at login.

4. Review the series once more (see Decisions).
5. Added after the first hardware tests, each as its own patch after

amdgpu for the iMacPro1,1 from this series, and its kernel-install hook
carries the series for later kernels.

## Decisions and failed attempts

Newest first.

- 2026-11-22: Wrap-up for the PR. Sleep test and a genlock reading after
  an hour (still -17 px) were done on a friend's iMac Pro (believed to be
  the same model), who reported all good; Kirk's own iMac's journal has no
  suspend or hour-long boot since `0003k`. Commit messages of
  `0003i`-`0003k` updated from "compile-tested only" to what was tested
  on the iMac Pro. Kirk added his Signed-off-by to `0003i`-`0003k`. Checks
  re-run for the whole series on 7.3.4-300 and 7.3.5-300: every patch
  applies (new ones offsets only), `BUILD_OK` with only the known
  `jpeg_v2_5.c` warning, checkpatch clean for `0003b`-`0003k`,
  `STATIC_CHECK_OK`. Whether to drop `0003d`/`0003e`/`0003j` (the
  per-frame reset is now opt-in and the tiles do not drift) stays open,
  Kirk's call later.

- 2026-11-20: Found the stall. Kirk's login tests: `imac5k_tile_lock=0`
  still stalled (4 `flip_done` timeouts, login failed with oo7-daemon
  timing out); `imac5k_genlock=0` logged in cleanly, 0 timeouts. Cause:
  `0003e` keeps the tiles in GSL group 0 for the per-frame reset, and a
  GSL group with the surface-flip purpose holds each member's flips until
  all have one (`0003j`'s delay bit was only part of it); the one-time
  sync leaves the group at once for this reason. With the reset off, the
  genlock debugfs read a constant -17 px (35 ns) over 10 minutes, the same
  as with it, and no seam tearing: the tiles share a reference clock and
  do not drift. Decision: `0003k` now makes `imac5k_genlock` default to 0
  (renamed "turn off the iMac Pro 5K per-frame tile reset"); the reset
  code stays as an opt-in. Removing `0003d`/`0003e`/`0003j` altogether is
  Kirk's call after more testing.
- 2026-11-20: `0003j` did not fix the login stall (Kirk: login hung on
  "authenticating", iMac panel grey, TB display fine; `imac5k_swap_lock`
  read 0). New in the log: after the fourth timeout, `dm_arm_vblank_event()`
  WARNs (amdgpu_dm.c:4561, from greetd's fbcon unblank) that crtc-0's
  previous page flip is still pending: the left tile's flip is never
  completed, so the swap lock was not (the only) cause. Patch `0003k` adds
  `amdgpu.imac5k_genlock` and `amdgpu.imac5k_tile_lock` (default 1) so
  Kirk can switch off `0003e`'s per-frame reset or `0003f`'s tile locks at
  boot and find the culprit, with `amdgpu.imac5k_merge=0` as the third
  test. Applies cleanly, builds.
- 2026-11-20: Kirk also reports the iMac powering off instantly (screen
  black, no shutdown) while CS2 was loading, before the `0003j` build.
  Logs of that boot still to come; looks like a hardware protection (heat
  or power), not the display code.
- 2026-11-20: Second hardware finding: after login (session switch) and
  after resume the panel froze 30-40 s with `[CRTC:85:crtc-0] flip_done
  timed out`; debugfs state shows crtc-0 = eDP-1 (left tile), crtc-5 =
  DP-1 (right tile), crtc-1 = DP-5 (Thunderbolt Display). Normal use is
  fine. Most likely cause: the GSL group `0003e` keeps for the per-frame
  reset also swap-locks flips (`DCP_GSL_DELAY_SURFACE_UPDATE_PENDING=1`
  in DCE 12's `setup_global_swap_lock()`), so a left-tile flip in a commit
  without the right tile's is never taken. DC itself does not wait for
  flips on DCE (`dc_post_update_surfaces_to_stream()` skips it). New patch
  `0003j`: `no_surface_update_delay` in `dcp_gsl_params`, honoured by
  DCE 12, set for the tile pair; `amdgpu.imac5k_swap_lock=1` restores the
  old behaviour so both can be compared. Same-frame latching of page flips
  stays with `0003f`. Applies cleanly, builds; checkpatch only wants
  Kirk's Signed-off-by. Not yet tested on hardware.
- 2026-11-20: Also seen on the iMac Pro, not caused by this series: after
  resume the Thunderbolt Display stays dark. The thunderbolt driver's
  `tb_resume_noirq` fails every config read (`tb_cfg_read: -108`), cannot
  rebuild the PCIe and DP tunnels, and the devices behind them stay in
  D3cold; replugging does not help, a reboot does. Probably the iMac
  Pro's `pcie_ports=compat` (needed against an SMP hang on resume), which
  turns off the PCIe port services Thunderbolt needs. Separate branch.
- 2026-11-20: Kirk's first hardware test: one 5120x2880 display at 200 %,
  no visible tearing. But the pointer vanished on the right half, while
  hover and clicks kept working there. Cause: DCE places the hardware
  cursor at a framebuffer position, not a screen position (legacy
  `dce_v10_0.c`: "avivo cursor are offset into the total surface";
  `dce110_set_cursor_position()` only adds the plane's source offset),
  and Byte's companion cursor subtracts the tile origin, which suits DCN
  only. New patch `0003i` adds the origin back on DCE. Applies without
  fuzz or offset after `0003h`, amdgpu builds (7.3.4, Fedora config,
  W=1, only the known warning); checkpatch only wants Kirk's
  Signed-off-by, which is his to add.
- 2026-11-20: Checks. Applied with
  `~/Documents/Code/vort2x-tools/gpu-series-check.sh` (Fedora SRPM + redhat
  patch, the installer's patch rule, Fedora's `.config` from kernel-devel,
  Fedora's `gcc-x86_64-linux-gnu`): on 7.3.4-300.fc45 every patch applies,
  the new ones with offsets only; the only fuzz in the series is the
  existing `0002` GMUX patch (fuzz 1, as before). `BUILD_OK`, one warning
  (`jpeg_v2_5.c`, pre-existing). Same on 7.3.5-300.fc45 (updates-testing).
  `checkpatch --strict` clean for 0003b-0003h; `check.sh` prints
  `STATIC_CHECK_OK`.
- 2026-11-20: Review findings from the patched 7.3.4 source. DCE's hw
  sequencer has `interdependent_update_lock = NULL` and
  `pipe_control_lock = dce_pipe_control_lock`, so the tile locks of
  `0003f` really run on DCE 12; `dce_pipe_control_lock` is DCE's
  `cursor_lock` too, so a cursor move on the panel during a held flip
  latches with the frame. DCE 12's `setup_global_swap_lock()` sets
  `DCP_GSL_DELAY_SURFACE_UPDATE_PENDING=1`, so with the GSL group kept set
  up (`0003e`) each tile's flip waits for the other: safe only because
  every panel flip carries both tiles (`0003g`: a left-tile flip mirrors
  the companion, anything else gets the full expansion). This is the
  riskiest part on hardware: a stall would show as a frozen panel and
  `flip_done timed out`; `amdgpu.imac5k_merge=0` turns it all off.
- 2026-11-20: Using the Fedora 7.3 port, not the 7.4 `patches/`: Fedora 45
  runs 7.3.x. The port was made for 7.3.5-200.fc44 against KAIT2EN's
  series, which is identical to VorT2x's (checked file by file).
- 2026-11-20: Kirk: before the VorT2x patches the iMac Pro ran 4K without
  tearing; with them, two separate tiles. Cause: VorT2x's 0003 is the
  earlier two-tile patch (167 changed lines, no merged output), not Byte's
  later merged-output patch (about 1000 lines) that the iMac Pro work builds
  on.
