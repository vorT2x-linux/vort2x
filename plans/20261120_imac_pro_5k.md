# iMac Pro 5K as one tear-free display

## Goal

On the iMac Pro (iMacPro1,1, Radeon Pro Vega 56/64, display engine DCE 12)
the 5K panel is two 2560x2880 tiles on two links. VorT2x's current series
carries the earlier two-tile 5K patch (0003, Atharva Tiwari) plus KAIT2EN's
0013 (adds the iMacPro1,1) and 0014 (scopes the quirk), both by Andre
Eikmeyer. That shows the panel as **two separate displays**: on Kirk's iMac
Pro after the VorT2x install he had to use 2560x1440 on one tile. Fedora's
own kernel gives a single 4K picture.

Bring in the work from `~/Documents/Code/imacPro_amdgpu` (private repo
`KirkDiamond/iMac5k_KaiT2en_support`): Byte's later "amdgpu: add support for
5K" (Atharva Tiwari, Ed Schofield), which merges the two tiles into one
5120x2880 output, plus Kirk's seven patches that add the iMac Pro and make
the merged output work on DCE 12 without a seam tear: per-frame genlock of
the right tile to the left, both tiles latched on the same frame, only
panel commits expanded to both tiles, and a debugfs file to measure the
genlock. iMac20,x (DCN) behaviour stays as Byte's patch has it.

## Decisions and failed attempts

Newest first.

- 2026-11-20: Kirk's first hardware test: one 5120x2880 display at 200 %,
  no visible tearing. But the pointer vanished on the right half, while
  hover and clicks kept working there. Cause: DCE places the hardware
  cursor at a framebuffer position, not a screen position (legacy
  `dce_v10_0.c`: "avivo cursor are offset into the total surface";
  `dce110_set_cursor_position()` only adds the plane's source offset),
  and Byte's companion cursor subtracts the tile origin, which suits DCN
  only. New patch `0003i` adds the origin back on DCE. Applies without
  fuzz or offset after `0003h`, amdgpu builds (7.3.4, Fedora config,
  W=1, only the known warning); checkpatch only wants Kirk's
  Signed-off-by, which is his to add.
- 2026-11-20: Checks. Applied with
  `~/Documents/Code/vort2x-tools/gpu-series-check.sh` (Fedora SRPM + redhat
  patch, the installer's patch rule, Fedora's `.config` from kernel-devel,
  Fedora's `gcc-x86_64-linux-gnu`): on 7.3.4-300.fc45 every patch applies,
  the new ones with offsets only; the only fuzz in the series is the
  existing `0002` GMUX patch (fuzz 1, as before). `BUILD_OK`, one warning
  (`jpeg_v2_5.c`, pre-existing). Same on 7.3.5-300.fc45 (updates-testing).
  `checkpatch --strict` clean for 0003b-0003h; `check.sh` prints
  `STATIC_CHECK_OK`.
- 2026-11-20: Review findings from the patched 7.3.4 source. DCE's hw
  sequencer has `interdependent_update_lock = NULL` and
  `pipe_control_lock = dce_pipe_control_lock`, so the tile locks of
  `0003f` really run on DCE 12; `dce_pipe_control_lock` is DCE's
  `cursor_lock` too, so a cursor move on the panel during a held flip
  latches with the frame. DCE 12's `setup_global_swap_lock()` sets
  `DCP_GSL_DELAY_SURFACE_UPDATE_PENDING=1`, so with the GSL group kept set
  up (`0003e`) each tile's flip waits for the other: safe only because
  every panel flip carries both tiles (`0003g`: a left-tile flip mirrors
  the companion, anything else gets the full expansion). This is the
  riskiest part on hardware: a stall would show as a frozen panel and
  `flip_done timed out`; `amdgpu.imac5k_merge=0` turns it all off.
- 2026-11-20: Using the Fedora 7.3 port, not the 7.4 `patches/`: Fedora 45
  runs 7.3.x. The port was made for 7.3.5-200.fc44 against KAIT2EN's
  series, which is identical to VorT2x's (checked file by file).
- 2026-11-20: Kirk: before the VorT2x patches the iMac Pro ran 4K without
  tearing; with them, two separate tiles. Cause: VorT2x's 0003 is the
  earlier two-tile patch (167 changed lines, no merged output), not Byte's
  later merged-output patch (about 1000 lines) that the iMac Pro work builds
  on.
