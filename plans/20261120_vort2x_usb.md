# vort2x-usb: a terminal USB creator for macOS and Linux

## Goal

Replace the plain-prompt bash script `scripts/macos/prepare-fedora-installer.sh`
with **vort2x-usb**, a full-screen terminal program (Rust + ratatui) that
makes the same VorT2x Fedora USB stick, on **macOS and Linux**. It looks
better (logo, menus, drive list with warnings, progress bars), and it no
longer mounts anything: the stick's boot partition is edited in memory and
written in one pass, then read back and verified.

This branch is the first step. The result on the stick is the same as
today's script: the Fedora ISO, plus in the EFI partition a VorT2x
`grub.cfg` (Fedora's kept as `grub.cfg.fedora-original`) and
`EFI/BOOT/vort2x/` with `vort2x-input-initramfs.img`,
`vort2x-wifi-initramfs.img` and `wifi-firmware.sha256`.

Not in this branch (each its own later branch, see IDEAS.md):

- release integration: CI builds the binaries, the kit zip carries them,
  and the `curl | bash` bootstrap starts vort2x-usb on macOS and Linux;
- firmware downloaded from a macOS Recovery image, and carrying the
  firmware for every T2 Mac;
- removing the bash script (only after vort2x-usb is tested on a Mac).

Until then the bash script stays and the release keeps using it.

## How it works

Same steps as the bash script, in this order:

1. **Kit**: read `installer-target.conf`, `installer-editions.tsv`,
   `grub.cfg.in` and `vort2x-input-initramfs.img` from the unpacked
   release kit (`--kit DIR`, default: the folder holding the binary).
   Same validation as `load_editions` (IDs, Fedora release URL path,
   size, SHA-256).
2. **Checks** (macOS on the T2 Mac): Secure Boot policy from NVRAM, Touch ID
   enrolment via `bioutil` as the calling user. Shown as info, as now.
3. **Edition**: menu with the target's default preselected, or `--edition`,
   or `--iso FILE` (identified by its SHA-256).
4. **Drive**: external whole disks only.
   - macOS: `diskutil list -plist external physical` + `diskutil info -plist`
     (`Internal == false`, `WholeDisk == true`).
   - Linux: `lsblk -J -b`; whole disks that are removable, hot-plug or USB,
     and hold no mounted system file system (`/`, `/boot`, `/boot/efi`,
     `/home`, swap).
5. **ISO**: reuse a verified copy in the download folder (default
   `~/Downloads` of the calling user), else download it with `curl` from
   Fedora's mirror list (up to 10 HTTPS mirrors, then the canonical and
   archive URLs), resuming `.part` files, checking size and SHA-256, as
   `download-fedora-iso.sh` does. Progress from the size of the `.part`
   file. Files end up owned by the calling user, not root.
6. **Firmware**: macOS: the files in `ioreg` `RequestedFiles` from
   `/usr/share/firmware/wifi`, plus BCM4377 Bluetooth files when
   `system_profiler` reports that chipset. Or `--firmware-dir DIR` (the
   only source on Linux for now). Same checks as today (exactly one
   `.trx`/`.clmb`/`.txcb`/`P-*.txt`, matching board names), then
   `SHA256SUMS` and a gzip'd cpio `newc` archive with `./vort2x-wifi-firmware/…`,
   entries sorted like `find . | LC_ALL=C sort`.
7. **Boot partition in memory**: read the ISO's volume label from the
   ISO9660 primary volume descriptor, render `grub.cfg.in`; find the EFI
   System partition in the ISO's GPT (type `C12A7328-…`), or in its MBR
   (type `0xEF`); load it into memory and edit it with `fatfs`: keep
   Fedora's `EFI/BOOT/grub.cfg` as `grub.cfg.fedora-original` (not
   overwritten if already there), write the new files, read them back.
8. **Confirm**: type `ERASE <disk>` (e.g. `ERASE disk4`, `ERASE sdb`).
9. **Write**: unmount the drive (`diskutil unmountDisk`; on Linux `umount`
   of its mounted partitions), write the ISO in 4 MiB blocks to the raw
   device (`/dev/rdiskN` on macOS) with the EFI partition's bytes replaced
   by the edited copy, `fsync`, then read the written range back and
   compare its SHA-256 with what was written (Linux: drop the block
   device's cache first with `BLKFLSBUF`).
10. **Done**: next steps as today (Option key, EFI Boot, etc.).

Administrator rights: needed only to write a real drive. vort2x-usb starts
`sudo` on itself before the full-screen UI opens, like the bash script.

`--target-file FILE` writes the stick image to a file instead of a drive
(no root, no confirmation). It lets the whole pipeline be checked without a
USB stick. `--plain` prints progress lines instead of the full-screen UI,
for scripted runs. `--list-editions` and `--list-drives` print and exit.

## Layout

`auto-installer/vort2x-usb/` (with the rest of the USB-installer code), its
own `Cargo.toml`/`Cargo.lock` like the apps, GPL-3.0-or-later, SPDX header
in every file.

- `src/main.rs`: options, root, which mode.
- `src/kit.rs`: target file and edition catalogue.
- `src/drives/{mod,macos,linux}.rs`: listing, checks, unmounting.
- `src/download.rs`: mirrors, `curl`, verification.
- `src/firmware.rs`, `src/cpio.rs`: firmware collection and archive.
- `src/image.rs`: volume label, partition table, EFI partition edit.
- `src/write.rs`: writing and read-back verification.
- `src/macos.rs`: Secure Boot and Touch ID checks.
- `src/ui/`: the ratatui screens and the state machine behind them.
- `README.md`.

Dependencies already used in the project: `anyhow`, `clap`, `flate2`,
`libc`, `plist`, `serde_json`, `sha2`. New: `ratatui` (with
`crossterm`) for the UI, `fatfs` for the EFI partition. Downloads use the
system `curl` (as now), so no HTTP library.

## Acceptance criteria

All run by me; nothing here needs a Mac booted from the stick.

- [x] `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and
      `cargo test` pass on macOS (this Mac) and in Fedora 44 (Docker).
- [x] Unit tests cover: catalogue validation (good and bad lines), target
      file parsing, volume label, GPT and MBR EFI-partition lookup,
      firmware checks (missing, duplicate, mismatched board names), the
      `ERASE` confirmation, the Linux drive filter (system disk refused)
      and the macOS `diskutil` plist parsing.
- [x] FAT test: on a FAT image made in the test, the edit keeps the
      original `grub.cfg` as `grub.cfg.fedora-original`, writes the new
      files with the right bytes, and running it twice keeps the original.
- [x] cpio test (Fedora 44): GNU `cpio -id` extracts vort2x-usb's archive
      to the same files and contents, and `sha256sum -c SHA256SUMS` passes.
- [x] End to end in Fedora 44 with the real Fedora 45 COSMIC ISO, the
      v0.2.1 release kit and test firmware, using `--target-file --plain`:
      the image is as long as the ISO; outside the EFI partition it is
      byte-identical to the ISO; in the EFI partition (read with `mtools`)
      `grub.cfg` equals `grub.cfg.in` with the ISO's label,
      `grub.cfg.fedora-original` equals the ISO's own `grub.cfg`, the input
      initramfs equals the kit's, and the firmware initramfs extracts with
      a passing `SHA256SUMS`.
- [x] The same end-to-end run on macOS (this Mac) gives an identical image.
- [x] `--list-editions` prints the catalogue; `--list-drives` runs on macOS
      and Linux without root and shows no internal disk.
- [x] The UI renders every screen without panicking at 80×24 and 120×40
      (ratatui `TestBackend`), in tests.
- [x] `docker run … check.sh` prints `STATIC_CHECK_OK`.

Hardware tests for the Tested section (a person): make a stick on a T2 Mac
in macOS and on a Linux machine, boot it, check Wi-Fi in the live system and
that the Fedora install picks up the firmware.
